## KAE-BLOCK-000286: Replication Manager Manual Routing

- Source IDs: `SRC-000211`, `SRC-000204`, `SRC-000225`, `SRC-000218`.
- Version scope: multi-version `Altibase_release` tool manual and
  `Altibase 8.1 verified source` tool manual.
- Source block refs: `SRC-000211/BLOCK-000843`, `SRC-000204/BLOCK-000842`,
  `SRC-000225/BLOCK-000835`, `SRC-000218/BLOCK-000834`.
- Alignment status: baseline generated from paired Korean authority and
  English extraction aids. Exact GUI dialog labels, screenshots, full
  workflow ordering, SQL generated by the tool, and runtime behavior still
  require target-version source-pack, installed-tool, or environment recheck.

Baseline:

1. Route Replication Manager manual work to the target tool-manual source
   first: `Altibase_release` for the multi-version Release 1.4 manual, and
   `Altibase_trunk` only when the request explicitly needs the
   `Altibase 8.1 verified source` Release 1.5 manual. Do not backport a
   trunk-only wording change or behavior claim into the release manual without
   exact source evidence.
2. Treat Replication Manager as a GUI tool for managing Altibase replication
   objects. It is not a substitute for the Replication Manual, SQL Reference,
   General Reference, installed JDBC driver evidence, or live replication
   status. Use this baseline to route GUI operations and then recheck the
   target replication SQL or runtime state when the answer affects production
   data movement.
3. Preserve system and compatibility boundaries before drafting setup
   guidance: CPU 800 MHz Pentium or better, memory 512 MB or more, disk space
   50 MB or more plus any required JRE space, screen resolution 1024 by 768 or
   higher, Windows and Linux packages, JDK or JRE 6 or later, and Altibase
   4.3.9 or higher. The Korean manual also records that the manual assumes an
   Altibase 7.1 database server; do not convert the GUI tool compatibility row
   into a guarantee for every server patch, platform, or driver.
4. Preserve package and installation boundaries. Replication Manager is
   provided as a ZIP package, installation is by unzipping the package into the
   desired directory, and uninstallation is by deleting the installation
   directory. For Linux, verify the JRE and environment variables before use;
   for Windows, verify the package-specific bundled JRE statement from the
   target manual or release note.
5. Preserve JDBC driver routing. Replication Manager can connect to different
   Altibase versions at the same time, but the user must import and select the
   JDBC driver appropriate for each target Altibase server. Recommended first
   draft guidance may tell the user to import the server-matching Altibase
   JDBC driver, name driver files distinctly, use `JDBC driver manager`, and
   select the correct `JDBC driver` in the connection dialog. Do not guess the
   driver file from the product version without installed file evidence.
6. Preserve connection fields and option names exactly: `Connection Name`,
   `Password`, `DB Address`, `DB Port`, `DB Name`, `JDBC driver`,
   `IP Address Type`, and `NLS for Client`. `Connection Name` is limited to
   up to 10 characters, must start with an alphabetic character, and may mix
   alphabets and numbers. `IP Address Type` supports IPv4 or IPv6. `NLS for
   Client` is not necessary when connecting to Altibase version 5.3.1 or
   higher.
7. Use the source-backed connection workflow for guarded first drafts:
   import the JDBC driver, add a database connection, run `Connection Test`,
   save the connection, connect to the database, perform the required
   replication administration task, disconnect, edit connection information
   only while disconnected from that database, manage `Extra Host IP` when
   needed, and remove unused connections only after confirming they are no
   longer needed.
8. Preserve the `Extra Host IP` warning. If an Altibase host has multiple IP
   addresses and another Altibase used one of those addresses as the
   `Remote Host IP` when creating a replication object, that address must be
   either the registered `DB Address` or an `Extra Host IP`; otherwise the
   relationship between the database and replication object might not display
   correctly in the `Map` pane.
9. Preserve the four-pane model: `DB Connections`, `Replication Pairs`, `Map`,
   and `Properties`. `DB Connections`, `Replication Pairs`, and `Map` interact
   with each other; `Properties` is read-only and displays selected-object
   properties. The six model objects are `Replication Object`,
   `Replication Target Table Object`, `DB Connections Object`,
   `DB Connection Object`, `Replication Pairs Object`, and
   `Replication Pair Object`.
10. Preserve DB Connections pane operations exactly: `Connect all`,
    `Disconnect all`, `Start all`, `Stop all`, `Quick Start all`,
    `New DB Connection`, `Collapse All`, `Expand to Replication Object`, and
    `Expand to Replication Table`. For `DB Connection Object`, preserve
    `Connect`, `Disconnect`, `Edit`, `Manage Extra Host IP`, `Remove`,
    `Start all`, `Stop all`, `Quick Start all`, `Create Replication`,
    `Create Full-mesh Replications`, `Join to Full-mesh`,
    `Create Replication Pair`, and `Drop Replications`.
11. Preserve Replication Object operations exactly: `Start`, `Stop`,
    `Quick Start`, `Sync`, `Sync Only`, `Drop`, `Edit Table List`, `Monitor`,
    `Show DDL`, and `Compare DDL`. `Sync` maps to
    `ALTER REPLICATION replication_name SYNC`; `Sync Only` maps to
    `ALTER REPLICATION replication_name SYNC ONLY`. Use the Replication Manual
    and SQL Reference route before generating final SQL or explaining all
    replication-state effects.
12. Preserve destructive and state-sensitive warnings. `Quick Start` and
    `Quick Start all` can cause loss of replication data not yet delivered to
    another node. `Drop Replications` requires all replication objects in the
    DB Connection to be stopped. `Drop` requires the selected replication
    object to be stopped. `Edit Table List` adds or removes replication target
    tables only for a stopped replication object.
13. Preserve pair and topology behavior without overstating it.
    `Replication Pair` means corresponding replication objects with the same
    name on two different nodes. `Create Replication Pair` creates a pair of
    replication objects at two DB Connections. `Create Full-mesh Replications`
    creates full-mesh replication objects for selected DB Connections, and the
    release manual example records 16 replication objects with the same name
    for four selected DB Connections. Recheck exact topology, object names,
    table lists, and runtime state before giving production instructions.
14. Preserve Map behavior as visualization and control, not as proof of
    replication health. The `Map` pane shows physical layout, status, and
    relationships among databases and replication objects. If a corresponding
    replication object cannot be located, release-source wording records an
    `Unknown` DB Connection display. Treat that as a routing clue requiring
    connection, host, Extra Host IP, and replication metadata checks.

Safe first checks:

- Ask for the Replication Manager release, target Altibase server version and
  patch, operating system, package name, JDK or JRE version, imported JDBC
  driver file, connection fields, IP address type, `NLS for Client` need,
  topology, replication object names, table lists, and whether the request is
  GUI usage, generated SQL, or runtime troubleshooting.
- For start, stop, quick-start, sync, drop, table-list edit, full-mesh, or
  pair-creation guidance, ask for current replication state, gap, sender and
  receiver status, object definitions, DB Connection list, Remote Host IPs,
  Extra Host IPs, and the intended validation and rollback path.
- For screenshots, GUI labels, package download, installed behavior, or
  generated DDL comparisons, use the exact source-pack block and installed
  tool evidence.

Stop conditions:

- Stop if the request depends on live replication state, undelivered logs,
  replication gap, topology, target patch, JDBC driver file, GUI error
  dialog, generated DDL, object definitions, network routing, or logs that
  the customer has not supplied.
- Stop if the request asks for production-ready start, stop, quick-start,
  drop, full-mesh, or sync procedures from this baseline alone. Route to the
  exact Replication Manager source block, the target Replication Manual, and
  live customer evidence.
- Stop if a request asks to infer Altibase replication behavior from generic
  database assumptions, Oracle-only replication patterns, or generic GUI tool
  behavior.

## KAE-BLOCK-000287: Replication Manager Release-Note Routing

- Source IDs: `SRC-000464`, `SRC-000443`, `SRC-000465`, `SRC-000444`,
  `SRC-000466`, `SRC-000445`.
- Version scope: Replication Manager 1.2, 1.3, and 1.4.
- Source block refs: `SRC-000464/BLOCK-000837`, `SRC-000443/BLOCK-000836`,
  `SRC-000465/BLOCK-000839`, `SRC-000444/BLOCK-000838`,
  `SRC-000466/BLOCK-000841`, `SRC-000445/BLOCK-000840`.
- Alignment status: release-note routing generated from paired Korean
  authority and English extraction aids. Exact package availability, download
  links, bundled libraries, and installed behavior remain source-pack or
  environment recheck items.

Baseline:

1. Route Replication Manager release-note claims to the exact release-note
   version. Do not merge Replication Manager 1.2, 1.3, and 1.4 changes into a
   single timeless feature claim unless the customer asks for a historical
   summary and the exact source IDs are preserved.
2. Preserve Replication Manager 1.2 scope: system requirements include
   800 MHz Pentium III or better, 512 MB memory or more, 50 MB disk free space
   excluding JRE needs, 1024 by 768 screen resolution or higher, Windows XP
   Vista 7 and Linux x86 packages, Java 6 or higher, and Altibase 4.3.9 or
   higher. Version 1.2 records `BUG-46683` for supporting databases with
   multiple IPs and `BUG-46677` for updating the GUI after `SYNC` completes.
3. Preserve Replication Manager 1.3 scope: system requirements include JDK or
   JRE 6 or higher, Windows x86 Win32 and Linux x86 GTK packages, and Altibase
   4.3.9 or higher. Version 1.3 records `BUG-47926` for providing
   `Create full-mesh replications`, `BUG-47927` for easily adding a newly
   added DB to a full-mesh replication object, `BUG-49483` for replacing
   embedded help with a GitHub manual link, `BUG-46876` for a partitioned
   table being represented as multiple partitions, and `BUG-49500` for
   changing logging from log4j to `JUL (java.util.logging)` due to
   `CVE-2021-44832`.
4. Preserve Replication Manager 1.4 scope: system requirements include JDK or
   JRE 6 or higher, Windows x86 Win32 and Linux x86 GTK packages, and Altibase
   4.3.9 or higher. Version 1.4 records `BUG-50573`, updating the JRE packaged
   in Replication Manager from version 6 to version 8. The 1.4 package names
   are `ReplicationManager_1.4.0-win32.win32.x86.zip` and
   `ReplicationManager_1.4.0-linux.gtk.x86.zip`.
5. Preserve library and package rows as release-note evidence. Do not treat
   open-source library tables, royalty-free image tables, archive names, or
   support-portal download text as proof of current distribution state.
6. Release notes can route feature-history answers and package-version
   questions. For operational GUI procedures, route to `KAE-BLOCK-000286` and
   the exact target manual. For replication SQL, state, compatibility, or
   data-loss risk, route to the Replication Manual, technical replication
   compatibility documents, and runtime evidence.

Safe first checks:

- Ask for the installed Replication Manager version, package filename,
  operating system, Java runtime, target Altibase version, and whether the
  user needs release history, installation/package information, or operational
  replication guidance.
- For a `BUG-*` answer, preserve the exact token, release version, source ID,
  and whether the token is a new feature or fixed bug in that release note.
- For download or package availability, require current customer or installed
  package evidence because this baseline records documentation evidence only.

Stop conditions:

- Stop if the user asks whether a package is currently downloadable, whether a
  bundled library is currently supported, or whether a release-note feature is
  present in an installed tool without providing installed-version evidence.
- Stop if the user asks for production-ready replication procedures from a
  release-note row alone. Route to the manual block, exact source-pack text,
  and customer runtime evidence.
- Stop if a request asks to infer tool compatibility from generic database
  assumptions, Oracle-only replication behavior, or release notes for another
  Replication Manager version.
