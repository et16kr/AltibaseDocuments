## Design Note

This report is the J001 remediation map. It intentionally changes documentation structure only by adding a durable inventory report under `GPTs/reports/`; it does not edit `GPTs/attachments/` or original source manuals. The source-backed basis for each row is the durable benchmark question record and its `source_refs`; later remediation jobs must still open the listed selected source files before adding or broadening any Altibase behavior in customer-facing attachments.

The inventory separates four fix classes:

- `content gap`: the expected fact or literal token is not matchable in the full current attachment set; later jobs must source-check and add an answer-ready item block if supported.
- `retrieval gap`: the item is matchable somewhere in full attachments but not in the reproduced lexical context for that question; later jobs should add aliases, headings, compact indexes, or cross-links.
- `answer synthesis gap`: the item is already in the reproduced lexical context but the answer omitted or weakened it; later jobs should use stricter answer patterns and denser item blocks.
- `judge calibration issue`: reserved for later calibration only after source and answer-path checks. This J001 pass does not classify any failed item as judge-only.

- Replayed `answer_runner.py` lexical context selection with `max_context_chars=180000` and `chunk_chars=8000`.
- Verified every reproduced context digest against `answers/answers.jsonl`; mismatches: `0`.
- Compared missed expected facts with selected context and full attachments using the same `judge_report.py` fact matcher.
- Compared missed required tokens with selected context and full attachments using the same literal-token matcher.
- Classified only observed failed-answer items; no benchmark thresholds or expected questions were changed.
