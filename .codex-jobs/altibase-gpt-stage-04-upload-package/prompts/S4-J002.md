## Specific Scope

Create the Stage 4 upload composition plan, manifest schema, crosswalk expectations,
and deterministic validation approach.

Expected outputs:

- `GPTs/reports/stage_04_upload_package_plan.md`
- `GPTs/reports/stage_04_upload_package_manifest.tsv`
- `GPTs/reports/stage_04_upload_package_validation.md`
- optional `GPTs/reports/scripts/validate_upload_package.py`
- `GPTs/upload_package/` directory may be created, but upload Markdown files must
  remain absent in this scaffold job.

The plan must decide or explicitly defer:

- whether the final package uses the existing 20 attachment filenames or merged files;
- how source-preserving, playbook, and answer-ready layers are represented within the
  20 Markdown file limit;
- how AID upload-content candidates will be selected, integrated, or deferred;
- required sections for each upload Markdown file;
- which package files may contain source IDs or block IDs as source-boundary metadata;
- which internal IDs must remain only in reports/crosswalks outside the package;
- how `APB-000014` and `CONF-000004` through `CONF-000009` are carried forward;
- deterministic validation checks for count, required sections, source routes,
  internal path leakage, CJK leakage, broken upload links, excluded sources, and
  upload-boundary hygiene.
